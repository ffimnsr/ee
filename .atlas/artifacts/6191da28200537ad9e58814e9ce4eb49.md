# Harness adoption apply behavior (verified 2026-11-24)

Question: does ee/harness2 automatically apply `<run-root>/adopted/.agents`, or is manual copy required?

Verdict: manual for the adopted harness tree. No automatic copy into active workspace `.agents`.

Evidence:
- `crates/ee-agent-harnessing/src/driver.rs:545-546`: chosen tree materialized only to `run_root.join("adopted")`.
- No other production call site writes the adopted tree into the workspace `.agents` root. `adopted` appears only in run-root resume/write/print paths.
- `crates/ee-cli/src/harness_cmd.rs:236-238`: CLI only prints `ee: adopted harness <path>`.
- `crates/ee-agent-orchestrator/src/provider_adapter/harness_command.rs:86-92` runs child with stdin null; `:314-347` child args contain no `--yes`. `/harness` therefore cannot approve reflection.
- Reflection is separate: `crates/ee-cli/src/harness_cmd.rs:841-852` requires approval then calls `save_entry`; `crates/ee-agent-orchestrator/src/user_experience.rs:748-760` writes `.agents/experience/<domain>/entries/<seq>-<slug>/EXPERIENCE.md` plus `harness/` snapshot. This archives the adopted tree; it does not overwrite active `.agents/guardrails.md`, `.agents/tool_guidance.md`, `.agents/scripts/`, `.agents/middleware.toml`, or skills.
- `crates/ee-agent-orchestrator/src/harness_source.rs:16-40`: active component discovery defaults to `HarnessSource::Workspace`; `Override(path)` is programmatic only.
- `crates/ee-agent-orchestrator/src/user_experience.rs:584-618` + `provider_adapter/prompt_bundle.rs:133-137`: written experience entries are auto-discovered into a bounded untrusted prompt catalog; `load_experience` reads EXPERIENCE.md lesson/edit rows, not the archived harness as active components.

Implication: to adopt a run, copy `<run-root>/adopted/.agents/*` into workspace `.agents/` manually, or configure `HarnessSource::Override` programmatically. `--yes` only gates the experience-library write, not harness application.
