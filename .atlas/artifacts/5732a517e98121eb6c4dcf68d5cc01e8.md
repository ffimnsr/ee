# Harness2 → ee agents mode improvement plan

Source: arxiv 2610.14224v1 (Google Harness2, recursive agent harnessing) + clone at `harness-example/harness2/harness2/` (core: proposer.py, recursion.py, library.py, selection.py, tree.py, context.py, ledger.py, prompts.py).

## ee current state (verified via Atlas)
- Components present: system prompt (provider `DEFAULT_SYSTEM_PROMPT` + I16 user agents), skills (`prompt/skills.rs` catalog + `load_skill`), subagents (`SubagentManager`, I16 subagent roles), memories (I27 `.agents/memories` + save/delete CRUD), commands (I17), model switch (I18), snapshot/diff/revert (I19), export (I22), usage analytics (I23), headless remote host (R1-R13), record/replay provider (ee-chat-completions).
- Missing vs Harness2's 8-component surface: no guardrails file (merged into system prompt), tool guidance is a hardcoded const (`prompt/tool_guidance.rs::TOOL_GUIDANCE`), no scripts dir convention, NO middleware/plugin in tool loop (0 graph matches), no trajectory/execution-record concept (0 matches), no reflector (0 matches), no experience library ("experience" 0 matches), no compose/selection stages, no budget ledger, no harness-edit validation (autotrigger/compile/trigger-line).
- Open item I26 (feature-flag registry) — prerequisite for gating any recursive harnessing.

## Improvement list (tiered)

### Tier 0 — prompt-content transfers, no new machinery
1. Editor-role prompt patterns into built-in tool guidance + delegate roles: divergence-first (cheapest fix = where runs disagreed), evidence-moment rule (every edit cites trajectory moment), KEEP_BASE is valid answer, form preference order skill > script > subagent > plugin > always-on prose, always-on prose is the expensive option, deliverable-shape rule (harness changes HOW not WHAT shape).
2. Grounding rule: verified workspace facts written as facts ("in this workspace X maps to Y") not rediscovery procedure; anchor + label; guessed fact worse than none.
3. Selector criteria (delivery/conformance/fidelity/internal-consistency/operational-fitness/finish) usable in review prompts and reviewer subagent role today.

### Tier 1 — small code, reuse existing surfaces
4. Experience library `.agents/experience/` per domain: entry = adopted component files + EXPERIENCE.md (cue/lesson/evidence/confidence) + INDEX.md; verdict vocabulary helped|hurt|no-observed-effect|confounded; NO_ENTRY when no execution contrast; streaming retention (only earlier tasks visible). Extend I27 memory frontmatter schema, reuse catalog/`load_memory` pattern.
5. `/reflect` command + post-task reflector session: diff candidate harness vs base, emit `<edits>` rows + one bounded lesson; lessons only from execution contrasts (paper: selection alone never establishes transfer).
6. Harness-edit validation layer (mirror `tree.py validate`): skill trigger-line rule (skill name must appear in always-on text, else dropped), scripts must exist + compile, subagent frontmatter, autotrigger repair, reserved names; run before any harness edit is adopted; one retry then inherit current harness.
7. Tool guidance → overridable file: workspace `.agents/tool_guidance.md` (untrusted plane, cannot override trusted policy) with const as default fallback; bounded + trust-labeled like skills/memories.
8. Guardrails as separate file component `.agents/guardrails.md` (always-on, short, trust-labeled) instead of merging into system prompt.
9. Middleware-lite: declarative `.agents/middleware.toml` hooks (warn-after-n-calls-without-artifact, append-hint-on-error-signature, verify-after-write) enforced in orchestrator tool loop — enforced not instructed; paper's biggest LAB gain component; aligns with I26 flags for rollout.

### Tier 2 — full ta[REDACTED] recursion
10. Execution-record capture: per-turn machine-readable rollout record (tool calls, errors, outputs, timings) as improver evidence; leak-guard redaction (reuse R12 redaction layer); truncation like `context.py _write_rollout`.
11. Propose stage: improver agent session (I16 role) reads task + reference rollout + harness tree in isolated context dir; two scoped candidates — INV (process/tool use) + DOM (domain knowledge); scoped beats generic (ablation: scoping worth 2.9-3.7 pts).
12. Probe: headless re-roll under matched config via ee-agent-remote host; candidate executed once; behavioral contrast vs reference.
13. Compose: merge/adopt-one/keep-base, each decision tied to named trajectory moment; unsafe-if-no-deliverable rule.
14. Selection: anonymized best-of-k deliverable pick, seeded shuffle ids, fenced ```choice parse, base output valid choice.
15. Budget ledger: R=4k rollouts / P=3k sessions identity per task (mirror `ledger.py`), feed into I23 analytics; hard caps + I26 flag gate; adaptive budget future work.

### Measurement
16. Harness-edit regression suite using ee-chat-completions record/replay; track #Steps + tool-error rate per task (paper E.4: error rate drops 20-37% post-refinement) in I23 analytics.
17. Leave-one-out library eval (paper E.2) to verify experience entries actually transfer.

## Paper cautions to encode
- Selection can pick weaker candidate (55 over 95) — coverage vs precision balance.
- Wrong premise propagates across candidates — probes must challenge shared assumptions.
- Single rollout = weak evidence; confounded verdict preferred over invented attribution.
- Library is adaptation not copying (only 2-10% of modified files keep ≥half their lines from an entry).

library −3.1/−1.8, scoping −2.9/−3.7, composition −1.6/−1.9 (WorkBuddy/JobBench). All three components matter; library biggest on WorkBuddy, scoping biggest on JobBench.
