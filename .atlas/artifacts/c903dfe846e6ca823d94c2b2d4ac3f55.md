# Agent setup UX + trust-store startup fix

## Warning root cause
`ee .ee.toml` passed a relative buffer path. `App::current_workspace_root()` used
`Path::new(".ee.toml").parent()` -> `Some("")`; `find_git_root("")` checked `.git`
relative to cwd and returned the empty path. `WorkspaceTrustStore` then called
`canonicalize("")`, which failed with ENOENT and surfaced as
`ee: warning: trust store I/O error: No such file or directory`.

Fix: `config::editorconfig::find_git_root` now anchors relative starts to
`current_dir()` and returns an absolute root. Regression test covers the empty
parent case.

## Setup manifest protocol
`ee-agent-protocol::setup::SetupInput` now supports:
- `required`
- `section`
- `choices: Vec<SetupChoice>`
- `advanced`
`SetupChoice` carries `value`, optional `label`, and optional `when` condition
(`SetupChoiceWhen { input, value }`) so choices can be scoped to an earlier input.

## OpenCode setup
`ee-agent-opencode` manifest now offers numbered choices:
- surface: zen/go (with endpoint descriptions)
- model and critic: only routable catalog ids, scoped by selected surface
- agent-internal rubber-duck mode: off/manual/automatic
- reasoning effort: low/medium/high
- advanced knobs marked `advanced` and grouped under "Advanced"

## Host wizard
New `crates/ee-cli/src/agent_setup_prompt.rs` renders sections, numbered choices,
conditional choices, an "Other" escape hatch, and an advanced-options gate.
Secrets now show `*` per character and erase on backspace.
Primary server name defaults to `agent`; external critic defaults to
`agent-critic`. Critic agent setup no longer overwrites `agents.default_agent`.
Rubber-duck prompts are grouped under an explicit ee-level critic heading and
the agent's own mode is labeled as independent.

## Agent pane naming
`AGENT_DISPLAY_NAME = "agent"` is now used for transcript nick, footer label,
and thread-name fallback. Configured server ids remain routing keys only.
