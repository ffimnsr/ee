# Runtime grammar default split + prebuilt language packs

## What changed
- Default release runtime now builds only `rust`, `toml`, `yaml`, sourced from `scripts/runtime-default-languages.txt`.
- `scripts/build-runtime.sh` gained `--all`, `--languages LIST`, `--language LANG`, `--strict`; default is the core list.
- `scripts/install-tree-sitter-runtime.sh` forwards `--all`/`--languages`/`--language`; default remains the core list.
- `scripts/language-pack.py` builds/verifies deterministic tar.gz packs with `manifest.json` (schema 1, package version, target, per-file sha256/size).
- Release CI builds the full runtime with `--all --strict`, emits `ee-language-pack-<version>-<target>.tar.gz` + `.sha256`, signs/attests/uploads it, and ships only the core runtime in the main archive.
- `install.sh` ignores language-pack assets when selecting the platform archive and prints the install hint.
- New `ee do runtime install <language>... [--all] [--pack FILE] [--sha256 HEX] [--force]` downloads the matching prebuilt pack from the GitHub release (or `EE_LANGUAGE_PACK_BASE_URL`), verifies archive SHA-256, validates the manifest, safely extracts only requested grammar libs into the user runtime root, and never needs cc/rustc/cargo/git.
- New default feature `runtime-packs` (`reqwest` blocking, `tar`, `flate2`); no-agent builds can still enable it explicitly.
- Build script emits `EE_BUILD_TARGET` for target-specific pack URLs.
- `ee do runtime build --strict` exits non-zero on any fetch/build failure so release packs cannot be incomplete.
- `ee do runtime` report prints `install with: ee do runtime install <language>` when grammar is missing.
- Tests: 6 runtime pack unit tests, CLI parser tests, shell tests for build/install scripts and language pack determinism.
