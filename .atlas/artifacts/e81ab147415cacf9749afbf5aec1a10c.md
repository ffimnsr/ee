# Agent-mode opt-in audit (static)

- Agents feature is default-on in `crates/ee-cli/Cargo.toml`; runtime `[agents] enabled=true` default, inert without `[agents.servers.*]`.
- Disabled-by-default user opt-ins found:
  - approval classifier: `EE_APPROVAL_CLASSIFIER=auto`, optional `EE_APPROVAL_CLASSIFIER_MODEL` (manifest inputs in ee-agent-openrouter/opencode; reader in both adapters)
  - session approval: `/approval autopilot|bypass` (default asks; bypass requires confirmation)
  - workspace-memory note persistence: `[agents.workspace_memory] persist_notes=true` (memory itself default-on)
  - web search provider: user-global `[agents.web_context]` provider + secret; direct fetch default-on; workspace may only tighten/disable
  - Browser Run: user-global account id + token secret ref
  - durable session log: `EE_SESSION_LOG_DIR` or `EE_SESSION_LOG_DURABLE=true`
  - durable recovery checkpoints: `EE_CHECKPOINT_DIR` (recovery default memory-only)
  - worktree isolation: `EE_WORKTREE_ISOLATION=1`, `EE_KEEP_WORKTREES=1`
  - agent plugins: `EE_AGENT_PLUGIN_PATH`
  - remote instruction URLs: `EE_INSTRUCTION_URLS`
  - telemetry: programmatic `TelemetryConfig` only, default false
  - workspace semantic memory: library opt-in only, not exposed via TOML
- Safety defaults: permissions absent = ask; approval alignment exact (heuristic host-global only); remote_permission_mode ask; read_only_modes ask/plan.
- Doc drift:
  - README says agents disabled at compile time by default; Cargo default includes agents.
  - `crates/ee-cli/src/config/constants.rs` says web context disabled by default; `AgentWebContextConfig::default().enabled=true` and config test asserts enabled.
  - `crates/ee-agent-orchestrator/src/approval_classifier.rs` doc names TOML `agents.approval_classifier="auto"`; actual frontend opt-in is env var.
- Validation: static inspection only; no tests run; working tree clean.
