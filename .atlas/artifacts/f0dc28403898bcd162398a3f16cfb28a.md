# ACP /usage feasibility — ee-agent-opencode

## Findings

- ACP v1 spec has stable slash-command support: agent MAY send `available_commands_update`
  after `session/new`; `AvailableCommand { name, description, input.hint }`; commands execute
  as ordinary `session/prompt` text. Dynamic replacement is allowed. Source:
  https://agentclientprotocol.com/protocol/v1/slash-commands and
  `agent-client-protocol-schema-1.9.1/src/v1/client.rs`.
- ACP has a stable `usage_update` session update: `used`, `size`, `cost { amount, currency }`
  only (context window + cumulative session cost). It has no rate-limit/quota window model.
  Grep of schema for `rate.limit`, `quota`, `weekly`, `monthly`, `rolling` returns nothing.
  So OpenCode Go rolling/weekly/monthly meters and workspace budgets are provider-specific and
  must be rendered as text (or carried in `_meta` for ee-aware clients).
- `ee-agent-opencode/src/usage.rs` already fetches both:
  - `GET https://opencode.ai/console/api/policies/current-budgets` (403 = no budgets)
  - `GET https://opencode.ai/zen/go/v1/usage` (403 = not subscribed to Go)
  `Meter { percent, limited, resets_at }` covers rolling/weekly/monthly; `Budget { per, limit_usd,
  spent_usd, resets_at, ... }` covers workspace policy windows.
- Only entry point today: `ee-agent-opencode/src/main.rs::print_usage` behind `--usage`
  (`Args.usage`). Module docs explicitly preserve "no startup path calls this module".
- Advertised commands come from `ee-agent-orchestrator/src/provider_adapter/conversation.rs::initial_commands`
  (compact, primary-agent, rubber-duck, reflect, harness, adopt, branch, revert, turn-diff,
  export-session, import-session, discard/resume when recovery enabled). No `usage`.
- ee-cli is already prepared: `PROVIDER_OWNED_SLASH_COMMANDS` includes `usage`
  (`crates/ee-cli/src/app/agent_pane/format.rs:454`), and
  `agents_require_advertised_provider_command` forwards it when the active session advertises
  `usage` (`app_mode.rs:197`). No client change needed.

## Recommended wiring

Prefer a provider decorator in `ee-agent-opencode` over adding `/usage` to orchestrator
`initial_commands` (the latter would advertise it to every orchestrator-based agent, including
OpenRouter, which has no usage endpoint).

1. Wrap `OrchestratorProvider` in an `AgentProvider` decorator in `ee-agent-opencode`.
2. Append `AvailableCommand::new("usage", "Show OpenCode budgets and Go rolling/weekly/monthly usage.")`
   to `SessionInit.commands` in `new_session`, `load_session`, and `resume_session`.
3. In `prompt`, detect exact `parse_slash_command(...).name == "usage"` before delegating,
   resolve `UsageProbe` via `env_or_dotenv`, call `usage::fetch_usage`, stream a bounded text
   report through `sink.agent_message_chunk`, return `PromptResponse` end_turn. Never call the
   model.
4. Keep advertisement static (no network at session start). A 403 at invocation means "not
   available for this workspace", not an error.
5. Optional: emit `SessionUpdate::UsageUpdate` for context/cost when known; never for quota.

## Test seams

- Decorator unit test: advertised command is present and `/usage` does not reach the delegate
  provider.
- `fetch_usage` is currently not injectable (hard-coded `EndpointTransport` in `get_json`).
  Add a small fetch trait or accept a transport factory to test the interception path without
  network. Existing `usage/tests.rs` covers parsing only.
