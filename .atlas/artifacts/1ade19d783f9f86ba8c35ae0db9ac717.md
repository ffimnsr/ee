# Why ee agent still prompted/denied inside trusted workspace

Current workspace digest: [REDACTED]

Trust state on disk:
- `~/.local/state/ee/workspace-trust/b7cb...toml`: `[trust] decision = "trusted"`, no rule entries.
- `~/.local/state/ee/mcp-trust/b7cb...toml`: two `ee` server grants, `acp:ee` and `stdio:ee --mcp-proxy`, both pin `ee_terminal_create` with `category = "execute"`.

Root cause: three separate mechanisms.

1. Workspace trust is not blanket exec trust.
   - `safe_read_enabled` only enables `OperationIdentity::Profile` entries where `is_safe_read_profile(profile)` is true (`crates/ee-cli/src/policy/profiles.rs:94`).
   - `trusted_write_enabled` only matches Write/WriteBatch (`crates/ee-cli/src/app/agent_bridge/app_decision.rs:535-562`); `_ => false` for terminal.
   - The built-in SAFE_READ registry has fixed commands (`ls`, `cat`, `head`, `tail`, `wc`, `stat`, `file`, etc.); `mk` is absent, so `profile_id_for_request` returns None.
   - Empty/missing document default is `global_default = FallbackEffect::Confirm` (`store.rs:238/272`, `app_trust.rs:453`), so unknown terminal commands prompt.

2. The MCP execute grant cannot cover the built-in ACP terminal path.
   - `McpServerGrant::validate` permits Execute only for `ee_terminal_create` (`policy/mcp_server_trust.rs:43`).
   - `server_trust_prompt_eligible` returns false when `prompt.mcp.is_none()` (`app_decision.rs:505-508`).
   - `ApprovalPrompt::terminal` sets `mcp: None` (`prompt.rs:404-405`).
   - The running session-6 transcript records: "no MCP servers were configured for this session (session/new carried no mcpServers)".
   - Session used ACP `terminal/create` / built-in `create_terminal`, not MCP `ee_terminal_create`; grant is inert for that surface.

3. The two later failures were hard denials, not approval prompts.
   - Evaluator checks `built_in_deny` first, before persistent deny, session deny, mandatory confirm, built-in allow, workspace gate, MCP server allow, session/persistent allow, fallbacks (`policy/evaluator.rs:86-143`).
   - `resolve_policy_deny` sends `AgentError::NonOverridableDenied` and returns before queueing UI (`app_decision.rs`).
   - `guarded-shell-parse-failure`: bounded shell parser fails closed for guarded commands (shell wrappers `sh/bash/zsh/fish/dash/cmd/powershell/pwsh` and `rm`-family) on `$`, backtick, `<`, unterminated quote/escape, nested `-c` parse failure, >16 KiB script, >256 tokens, >128 components, or depth >8.
   - `special-file-mutation`: `inspect_special_file` denies a redirection/tee/dd target whose `symlink_metadata` file type is neither regular file, directory, nor symlink — e.g. `/dev/null`, devices, FIFOs, sockets (`policy/safeguards.rs:329-335`, `168-193`). Cwd/executable location inside workspace is irrelevant.

Implication: even if the agent called MCP `ee_terminal_create`, the same safeguard deny would still win. Trust grants are allow layers, not overrides of `built_in_deny`.
