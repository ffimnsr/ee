# Upstream harness2 adoption behavior (verified 2026-11-24)

Path checked: `harness-example/harness2` (upstream Python release).

Verdict: no `adopted/` directory and no automatic apply to the developer's project/workspace. Selected harness persists under the run tree and, when reflection yields a valid lesson, in the per-domain library. Using it outside harness2 requires manual copy.

Evidence:
- `harness2/core/recursion.py:283-287`: candidate trees written to `work_dir/harnesses/<label>`.
- `harness2/core/schedule.py:578-588`: `selection.reflect_adoption(...)` runs automatically after a successful selection when a mode library exists. No approval prompt.
- `harness2/core/schedule.py:597-616`: selected tree obtained from `r.trees`; `mode_lib.add(...)` stores it only when the reflection result satisfies `has_experience` (cue + lesson + evidence).
- `harness2/core/library.py:15-23`: layout is `<root>/<run-tag>/<mode>/<domain>/INDEX.md`, `.../harnesses/<task>/harness/<rel>` (full adopted tree), `.../harnesses/<task>/EXPERIENCE.md`.
- `harness2/core/library.py:106-152`: `add()` writes the adopted tree and EXPERIENCE.md, rebuilds INDEX.md.
- `harness2/core/schedule.py:737-780`: `run_domain` threads the library forward across tasks. It is evidence for later tasks, not an installed base harness.
- `harness2/core/schedule.py:670-671`: each task's base tree still comes from `adapter.base_harness()` (benchmark baseline).
- `harness2/cli/_common.py:70-88`: runs under `<runs>/adapt`, library under `<runs>/library/<bench>/<k>/<variant>`.
- `harness2/substrate/codex.py:106-147` and `opencode.py:184-199`: harness trees are staged into temp/rollout workspaces for execution only.
- No CLI `apply`/`adopt` command; `pyproject.toml` scripts are run/judge/report/setup/check/demo/bridge only.

Contrast with ee adaptation: ee writes `<run-root>/adopted/.agents`, does not apply it, and reflection library writes are approval-gated. Upstream harness2 updates its run-scoped library automatically but still does not touch the user's project `.agents`.
