# Grammar offload feasibility (2026-11-23)

## Current state
- 58 configured runtime languages, 55 unique grammar libraries (shared grammar libs).
- `crates/xi-core-lib/src/runtime_loader/builtin.rs` has 20 legacy crate-sourced grammars.
- `crates/xi-core-lib/src/runtime_loader/builtin_catalog_generated.rs` has 38 git-pinned grammars.
- Release builds all languages: `.github/workflows/release.yml` calls `scripts/build-runtime.sh --force ...`; script hardcodes `ee do runtime fetch --all` and `ee do runtime build --all`.
- Installer copies full runtime to user root: `install.sh` `RUNTIME_DIR_DEFAULT="${DATA_HOME_DEFAULT}/${PACKAGE_NAME}"`.
- Runtime loader is already lazy per language (`load_language_for_canonical_id` loads one `.so` on demand), so bundling all does not load all parsers at startup.

## Measured sizes (local target/release-runtime)
- 55 grammar `.so`: ~49 MB uncompressed; ~5.4 MB gzip (tar.gz of grammars dir).
- Queries: 4.7 MB / 346 dirs uncompressed; ~324 KB gzip.
- Retain rust+toml+yaml: ~1.36 MB uncompressed; ~176 KB gzip.
- Official x86_64-linux-musl release asset: 34.1 MB tar.gz.
- Grammars are ~16% of release archive; majority of installed runtime disk.
- 37 grammar libs under 500 KB + rust: 6.6 MB, offload 17 = 42.4 MB.
- 40 libs under 1 MB (rust forced): 8.6 MB, offload 14 = 40.4 MB. Naive threshold drops common cpp/bash/elixir/ruby/php; curate instead.

## Activation gaps
- `ee do runtime build --language <lang>` exists and defaults output to user runtime root, which loader searches. But on-demand build needs:
  - C compiler via `cc` (`compile_parser_shared_library`).
  - `rustc -vV` via `effective_host_triple()` unless HOST is set.
  - For 20 crate-sourced builtins: cargo registry / `cargo fetch`.
  - For 38 git-sourced catalog entries: `git` + network.
- No prebuilt grammar downloader, no checksum/cosign verification path for language packs.
- Release users typically lack rustc/cargo/compiler, so activation is developer-only.
- `RuntimeLanguageConfig.enabled` only hides a language in merge; it does not acquire a grammar.

## Missing grammar effect
- `tree_sitter_support::syntax_feature_availability`: syntax_spans, semantic_motions, reindent all false.
- Fold/document_symbols/tags call `.ok()?` and degrade silently.
- Line/block comment toggles still work from metadata; LSP unaffected.
- Only `ee do runtime health` / `ee language` reports Missing; no in-editor prompt.

## Recommendation
1. Keep full default release unless disk footprint is hard requirement.
2. Add `--languages`/`--core` filter to `scripts/build-runtime.sh` and `scripts/install-tree-sitter-runtime.sh`; optional minimal artifact variant.
3. If default shrinks, ship signed prebuilt language packs per target and add `ee do runtime install <lang>` (sha256 + cosign), extracting into user root. Do not require local compilation.
4. If compile-on-demand remains, document toolchain prerequisites, migrate builtin crate sources to git sources or ship source archives, and make host-triple detection not require rustc.
5. Filter query dirs too for minimal package (`copy_all_bundled_runtime_queries_to_runtime` currently copies all 345).
6. Add tests: package contents, single-language install, missing-grammar degradation, signature verification, hot pickup without restart.

## Verdict
Directionally good for installed size. Bad as default if only rust/toml/yaml because activation is not user-ready and common languages lose syntax. Prebuilt packs or optional minimal build are the safe paths.
