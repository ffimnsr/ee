# Fix: turn system notices now collapse with response groups

## Problem
`-!- trusted workspace terminal`, `-!- Create terminal`, and `-!- Read terminal output` were appended through `AgentThreadUi::push_system`, which stored `TranscriptItem::System` without a response group. `render_agent_transcript` only hides items whose `response_group_for_item` is `Some` when the group is collapsed, so these notices stayed visible outside the collapsed response group.

## Change
- `TranscriptItem::System` gained `response_group: Option<ResponseGroupId>` with serde default for older journals.
- New `AgentThreadUi::push_turn_notice` attaches the active response group; `push_system` stays global for lifecycle and slash-command output.
- Client request dispatch, permission resolution, trust/auto-approval summaries, ACP v2 auto permission, native agent read/write, and validation notices now use `push_turn_notice`.
- Grouping helpers (`response_group_ids`, `has_response_group`, `response_group_for_item`, fork cutoff helper) recognize grouped system notices.
- Regression test asserts a collapsed group hides a grouped notice while a global notice stays visible.

## Validation
- `cargo fmt --all -- --check`
- `cargo clippy -p ee-cli --features agents --lib --tests -- -D warnings`
- targeted tests: new transcript regression, `tests::agent_pane::transcript_tests` 18 passed, `ui::tests` 43 passed, `archive_tests` 6 passed, `slash_tests` 23 passed
- `cargo check -p ee-cli --features agents --bins`
- One full `tests::agent_pane` run hit the existing flaky reconnect test; it passed on exact isolated rerun.
