# Implemented MCP server trust (2026-11-24)

Feature: host-local, workspace-trust-gated MCP server grants for the built-in `ee` MCP surface.

## What landed

- `crates/ee-cli/src/policy/mcp_server_trust.rs`
  - `McpServerTrust`, `McpServerGrant`, `McpServerToolGrant`.
  - Pinned matching on canonical workspace + server + transport identity + tool name + schema version + side-effect category.
  - `McpServerTrustCandidate` with preview fields for the approval UI.
  - `pinned_server_tools` derives an application-owned list: read tools with approval `none`, plus non-content-bearing safe write tools (`ee_apply_code_action`, `ee_format_file`, `ee_rename_symbol`). Execute, delete/move, content-bearing writes, memory mutations, network tools excluded.
- `crates/ee-cli/src/mcp_trust.rs`
  - Owner-only, atomic, workspace-keyed store at `$XDG_STATE_HOME/ee/mcp-trust/<workspace_hex>.toml`.
  - Strict TOML parsing; duplicate grant/transport/tool/id rejection; identity mismatch; owner-only permissions; malformed documents fail closed.
  - `ee do mcp trust grant|revoke|status`; grant requires a `trusted` workspace decision.
- Evaluator
  - `PolicyInput.mcp_server_trust`.
  - New `mcp_server_allow` layer after workspace gate, before session/persistent allows. Deny/safeguard/mandatory-confirm still win.
  - `DecisionReason::McpServerAllow`; trace now 12 layers.
- App/UI
  - `ApprovalPrompt.mcp_server_candidate`; `ApprovalChoice::AllowServer`; label `Trust MCP server (pinned tools)`.
  - Preview/confirmation, persistence-failure denial, workspace-trust gate, cache reload.
  - Auto-allow path emits `trusted by MCP server grant <id>` and dispatches without per-rule usage.
  - `/permissions` summary/list/inspect/revoke/reset includes MCP server grants.
- Tests
  - Pinned matching, schema/transport/workspace/args drift, dangerous-category rejection, deny precedence, store permissions/identity/malformed/duplicate handling, E2E UI grant + varied arguments + untrusted inertness.
- Docs: README MCP server trust section, CHANGELOG, ISSUES section.

## Scope note

External `[mcp.servers]` entries are forwarded to agents and remain agent-owned; ee does not mediate their tool calls. Resources in the built-in ee proxy are not exposed. The grant therefore covers the editor-mediated ee MCP tools that actually reach approvals.
