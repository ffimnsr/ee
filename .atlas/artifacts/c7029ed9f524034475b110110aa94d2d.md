# Standard MCP JSON configuration (2026-11-26)

Goal: load the ecosystem-standard `mcpServers` JSON shape alongside explicit `[mcp.servers]` TOML without weakening trust or merge rules.

## Sources

- User: `$XDG_CONFIG_HOME/ee/mcp.json` (works without a user `config.toml`).
- Workspace: `<dir>/.agents/mcp.json` for every directory in `.ee.toml` discovery; `root = true` stops discovery above that directory.
- System: `/etc/ee/config.toml` only (no system JSON layer).

## Merge order

1. `/etc/ee/config.toml`
2. `$XDG_CONFIG_HOME/ee/mcp.json`, then `$XDG_CONFIG_HOME/ee/config.toml`
3. legacy `~/.ee.toml` when XDG config is missing
4. ancestor directories outermost to innermost: `.agents/mcp.json`, then `.ee.toml`

Explicit TOML wins on duplicate ids in the same directory; a deeper directory outranks a shallower one. Workspace JSON env/header values keep `ConfigLayerKind::Ancestor` provenance, so `secret:[REDACTED] refs still require workspace trust.

## Parser behavior

New `crates/ee-cli/src/config/mcp_json.rs`:

- `mcpServers` object; unknown top-level and per-server fields ignored for client compatibility (`$schema`, `autoApprove`, `alwaysAllow`, ...).
- Local: `command`, `args`, `env`, `cwd`, `timeout_ms`; remote: `url`, `headers`, `timeout_ms`.
- `transport` or `type` accepts `stdio`, `http`, `streamable-http`, `streamablehttp`; inferred from `command`/`url` when absent.
- `disabled = true` or `enabled = false` skips the entry.
- HTTP+SSE (`transport: "sse"` or inferred `/sse` URL path) is reported and skipped.
- Ambiguous `command` + `url`, missing required field, invalid URL, and invalid env secret grammar skip only that server.
- Relative `cwd` resolves against the workspace directory for `.agents/mcp.json` and against `$XDG_CONFIG_HOME/ee` for the user file.
- 1 MiB size cap; malformed/oversized files are reported and skipped as a whole.

## Wiring

`discover_config_layers_with_env` now returns ordered `ConfigSource::{Toml, StandardMcp}` entries plus the TOML-only `layers` view. `load_config_with_env` merges standard entries through the existing `EditorSettings::merge_mcp_toml`, so trust tagging, transport mismatch replacement, and secret validation are reused. `config_search_report_with_env` appends imported files with note `standard MCP JSON` for `ee do doctor`.
