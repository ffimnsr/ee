# ACP v2 subagent exposure audit

## Verdict

Our subagents are internal orchestrator workers, not ACP child sessions. This is
spec-compliant because exposure is optional: the ACP v2 subagents page says an
Agent may use subagents without exposing them and report results through the
parent.

## Current behavior

- `crates/ee-agent-orchestrator/src/subagents/mod.rs` documents subagents as
  logical in-process `LoopEngine` runs sharing the parent tool registry.
- `crates/ee-agent-orchestrator/src/subagents/manager.rs:650-653` creates an
  `UpdateSink` with a dummy `SessionId("subagent")` and immediately drops the
  receiver: "Subagents stream no updates to the client".
- Client sees only the parent-level `delegate_task` tool call, progress/status,
  and the bounded handoff/result. Child thoughts, plans, tool calls, and text are
  invisible.
- Background children return an id immediately; completion arrives as a system
  reminder in the parent at the next step.
- Child tool permissions use the parent's `ClientBridge`, so they are attributed
  to the parent session, not a child session.
- `ee-cli` has no child-session UI: `/tasks` reports
  "subagent tasks: unavailable; current ACP host advertises no ta[REDACTED]
  capability" (`crates/ee-cli/src/app/agent_cmds` area, exact string in
  `app_commands.rs:346`).
- No `subagent_update`, child `sessionId`, `session_message`,
  `session_message_chunk`, child `usage_update`, `config_option_update`, child
  state mirroring, or restricted child methods.

## Dependency gap

`agent-client-protocol` 2.2.0 pulls
`agent-client-protocol-schema` 1.9.1. Grep for `subagent` in that schema
returns nothing. The published ACP v2 subagents spec is therefore ahead of the
locked SDK; typed support requires an SDK/schema upgrade first.

## What exposing would require

1. Upgrade the ACP schema to one with v2 `subagent_update` and
   `session_message`/`session_message_chunk`.
2. Give every subagent a stable child `SessionId` (the internal `SubagentId`
   exists, but is not an ACP session id).
3. Reuse/forward the child `UpdateSink` instead of dropping the receiver, and
   emit the parent `subagent_update` announcement before any child update.
4. Route child permission/elicitation requests with the child `sessionId` and
   advertise `capabilities.cancel`.
5. Mirror child state into the parent `subagent_update`; report child
   `config_option_update` and `usage_update`; parent cost includes descendants.
6. Report parent→child messages as child `session_message` views, and optionally
   the outgoing parent view.
7. Implement v2-only translation; v1 has no subagent surface.
8. Add host/ee-cli rendering/reducer support and replay/resume behavior.
9. Persist child associations; checkpoint subagent tree state already exists.

Internal `ChildRegistry` (`crates/ee-agent-orchestrator/src/child_registry.rs`)
already tracks child state/progress and could back the exposed state, but it is
not connected to the ACP outbound channel.
