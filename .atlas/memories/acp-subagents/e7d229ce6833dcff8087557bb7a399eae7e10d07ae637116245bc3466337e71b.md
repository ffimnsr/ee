ACP v2 subagent exposure audit: our subagents are internal in-process LoopEngine workers, not exposed as ACP child sessions. `subagents/manager.rs:650-653` creates a dummy `SessionId("subagent")` sink and drops the receiver, so child updates never reach the client. Client sees only parent `delegate_task` tool call/result. This is spec-compliant because ACP v2 subagents are optional. Locked `agent-client-protocol-schema` 1.9.1 has no `subagent` types, so typed exposure needs an SDK upgrade plus child SessionId/announcement/update forwarding, session messages, state mirroring, child requests/cancel, usage/config, v2 translation, host/CLI UI, and replay. `ee-cli` currently reports subagent tasks unavailable.
