Git runs pre-commit hooks (and thus the suite from `.githooks/pre-commit`) with a relative `GIT_INDEX_FILE=.git/index`. Child `git worktree add --detach` uses that inherited index path inside the new linked worktree, where `.git` is a file, producing `fatal: .git/index: index file open failed: Not a directory`. Not random flakiness: reproducible with `env GIT_INDEX_FILE=.git/index git -C <repo> worktree add --detach <path> HEAD`. Fix: `crate::workspace_isolation::git_command` builds every explicit-root git command with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_PREFIX`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES` removed; production `git()` and `workspace_snapshot::git_files` plus orchestrator test helpers reuse it. Regression test `workspace_isolation::tests::git_command_clears_inherited_repository_identity`; full orchestrator suite passes under `GIT_INDEX_FILE=.git/index`.
