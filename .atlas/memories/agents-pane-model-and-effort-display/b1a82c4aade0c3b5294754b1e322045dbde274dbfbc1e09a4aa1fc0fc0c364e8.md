Implemented in ee-cli agents pane:
- `app_models::current_model_id(config_options, session_model, agent_config)` and `current_effort(config_options, agent_config)` resolve from ACP option first, then `AgentThreadUi::current_model`, then agent process env/argv (`*_MODEL`/`*_REASONING_EFFORT`, side-slot keys excluded).
- `AgentThreadUi::current_model` records accepted `session/set_model` switches because ACP does not echo the model back. `AgentPaneState::pending_thread_action` is now `PendingThreadAction { thread_index, session_model, reply }`; `pump_thread_action_reply` sets `current_model` on success only.
- `/status` prints `model:<id> effort:<level>`; footer adds `model:… | effort:…` fitted to remaining width, preferring effort when only one fits; context usage stays right-aligned.
- Agent config option route (advertised `model`/`ThoughtLevel`) wins and updates via snapshot; orchestrator (OpenCode/OpenRouter) advertises only `effort` config id, so `/model` uses `session/set_model` + local memory.
Tests: footer_tests (10), mode_config_tests model switch now asserts current_model + /status, app_models 4 tests. clippy/fmt clean.
