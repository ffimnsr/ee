# Language Catalog Parity — Design + Plan

Status: **mock design, pending review** · Scope: `docs/src/languages` of `zed-industries/zed` @ `main`

## 1. Goal

Extend ee language capability to match Zed's documented language catalog:

- **Tree-sitter grammar sources** (grammar crate + version/symbol, or git source) for every language documented in `zed/docs/src/languages/*.md`, wired into ee's runtime grammar fetch/build pipeline.
- **Bundled default LSP servers** for the same set, matching Zed defaults: server id, binary command, args, file routing, workspace identifiers.

Tooling: a sync+generator pipeline so the catalog is reproducible when Zed docs move upstream.

## 2. Terminology

- Tree-sitter artifacts are grammars (parser libraries), not servers. No grammar server exists.
- LSP servers are the language servers (gopls, rust-analyzer, ...).
- ee today: 20 builtin grammars + 31 bundled LSP servers + ~500 bundled query dirs (Helix-style corpus).

## 3. Current State (verified)

### Grammar side — backend, `xi-core-lib`

- `crates/xi-core-lib/src/runtime_loader/builtin.rs` `builtin_runtime_components()`: 20 languages, each `RuntimeLanguageConfig { grammar: RuntimeGrammarConfig { library, symbol, source: RuntimeGrammarSource::Crate(name, version) } }`, plus `aliases`, `supported_query_kinds`, `LanguageMetadata` (line/block comments, indentation, unsupported semantic targets).
- `RuntimeGrammarSource` supports `Crate` and `Git` (types.rs L196); `grammar.rs` already implements `fetch_git_grammar_source` + git pinning (rev/tag/branch). **Git is the catalog source of choice for this work; crates.io is not used for new entries.**
- Runtime pipeline: `scripts/build-runtime.sh` → `ee do runtime fetch --all` (materialize crate/git sources into `--source-root`) → `ee do runtime build --all` (compile → `.so` → `--output-root`), per-language staging via `grammar_layout.rs`.
- Queries bundled from `runtime/queries/<query_lang>/` (folds/highlights/indents/injections/locals/rainbows/tags/textobjects); coverage ≈ 500 languages — essentially all Zed-doc languages already have query dirs (small gaps: asciidoc, biome, emmet, roc, uiua, yarn).
- Test grammars: `crates/ee-ts-test-grammars` (20 grammars compiled in for tests).

### LSP side — backend plugin, `xi-lsp-lib`

- `crates/xi-lsp-lib/src/types.rs` `Config::bundled()` (L115-526): 31 servers hardcoded via `bundled_language(...)` helper + `language_servers` map (id → attach language ids).
- `ee-cli` `LspSettings::default()` = `PluginLspConfig::bundled()` mapping; per-layer overrides in `.ee.toml`/config.toml unchanged. No frontend changes required.

### Boundary (RULE.md)

- Backend owns: grammar catalog (runtime provisioning), LSP protocol/config plumbing (`xi-lsp-lib`).
- Frontend owns: user/workspace config overrides, parser choice per filetype.
- This work adds backend-side *defaults only*; override layers untouched. No RULE.md change needed.

## 5. Design

### 5.1 Source of truth + generation pipeline

```
zed docs (raw.githubusercontent, 71 files)
        │  scripts/language-catalog/sync.sh (bash + python3 stdlib, no new deps)
        ▼
scripts/language-catalog/overrides.toml   ← curated: binary names/args/init options,
        │                               file types, comment styles, git-source
        │                               fallbacks (verified by hand once)
        ▼
references/language-catalog.json  ← checked-in generated manifest
        │  scripts/language-catalog/generate.py
        ▼
generated Rust catalogs (checked in, "GENERATED FILE — do not edit" header):
  crates/xi-core-lib/src/runtime_loader/builtin_languages/…rs  (grammar entries)
  crates/xi-lsp-lib/src/lsp/bundled_defaults.rs                 (server entries)
```

- Docs supply: grammar repo URL, LSP name. Overrides supply: binary command/args, routing (extensions/filenames/workspace id), init options, line/block comments, indentation strategy, and repo corrections when the doc link points at a monorepo or stray fork.
- Grammar resolution at sync time: doc-linked repo → `git ls-remote` → head rev pinned into the manifest → `RuntimeGrammarSource::Git { url, rev }` (branch/tag recorded too, rev wins). No crates.io lookup, no semver guessing. Existing git fetch path (`fetch_git_grammar_source`, rev/tag/branch pinning) used end-to-end; only catalog entries are new.
- Existing 20 builtin entries keep their current crate sources — migration to git is optional follow-up, not part of this work.
- Regeneration is explicit (`scripts/language-catalog/sync.sh --refresh-remote`), not on every build. Pins are exact; upgrades are deliberate PRs.

### 5.2 Grammar catalog layout (file-size rule compliance)

`builtin.rs` `builtin_runtime_components()` is ~365 LOC today and must stay < 1k. Move the table out:

- New module `crates/xi-core-lib/src/runtime_loader/builtin_languages.rs` splitting by family:
  - `web.rs` (html, css, javascript, typescript, astro, svelte, vue, glimmer…)
  - `compiled.rs` (c, cpp, csharp, rust, go, zig, ocaml, nim, kotlin, scala…)
  - `scripted.rs` (python, ruby, lua, luau, elixir, erlang, julia, r, …)
  - `data.rs` (json, yaml, toml, proto, prisma, sql, hcl, jsonnet…)
  - `misc.rs` (diff, make, fish, powershell, rst, yara, rego…)
- Keep `builtin_language!` + `metadata!` macros in one shared macro module; each family module exposes `fn entries() -> Vec<(String, RuntimeLanguageConfig)>`; `builtin_runtime_components()` concatenates. `builtin.rs` shrinks to loader wiring only.
- Generated file = one family module (e.g. `generated_zed.rs`) or per-family generated blocks; generator emits `include!`-style source. Decision at implementation: single `generated.rs` per crate is simplest and keeps diff reviewable.

Entry shape — every new entry carries a git source with exact rev:

```rust
builtin_language!(
    "zig",
    "tree-sitter-zig",
    "tree_sitter_zig",
    ["zig", "zir"],
    metadata!(LineCommentStyle::Token("//"),
              BlockCommentStyle::Tokens { open: "/*", close: "*/" },
              IndentationStrategy::TreeSitter, &[])
    .with_git_source(
        "https://github.com/tree-sitter-grammars/tree-sitter-zig",
        "<sha pinned by git ls-remote at sync time>",
    ),
);
```

Macro gains a `with_git_source` variant (or table form) mapping to `RuntimeGrammarSource::Git`; manifest fields: `url`, `rev` (required), `branch`/`tag` (informational).

`Languages` definitions (file-type → language) extended in same table; `file_types` from overrides (mirrors Zed `path_suffixes`).

### 5.3 Bundled LSP defaults layout

`xi-lsp-lib/src/types.rs` `Config::bundled()` is already a ~410-LOC single fn — split out:

- New `crates/xi-lsp-lib/src/lsp/bundled_defaults.rs`: macro-generated `pub fn bundled() -> Config` from a const table; per server: `id, language_name, command, args, extensions, filenames, supports_single_file, workspace_identifier, env, initialization_options`.
- `types.rs` calls it; keeps `Config`/`LanguageConfig` types. `bundled_defaults.rs` target < 1k with per-family submodules if needed.
- `ee-cli` `config/lsp.rs` needs **zero changes** (maps plugin config). `CONFIG_TEMPLATE` comment example stays generic; optionally add 3-4 realistic commented examples.

### 5.4 Queries

- Verify query-dir presence per new language (`runtime/queries/<query_language>/`); backfill missing dirs from Helix corpus copy (existing provenance) or minimal highlights for fringe (roc, uiua not in corpus → hand-minimal or defer).
- Injection coverage check for embedded langs: astro (js/ts/css), vue, svelte, gleam (javascript), helm (yaml), haskell literals — dirs already exist; spot-verify at load test.

### 5.5 What we do NOT do

- No per-language nav/UI work, no debugger adapters, no formatter defaults beyond what docs specify.
- No removal of existing 20/31 entries; catalog only grows.
- No automatic runtime sync from live Zed (lv): generated files are checked in, reviewed, version-pinned.

## 6. Plan

### Phase 0 — Issue + scaffolding
- Add ISSUES.md section "Language Catalog Parity" with phases below + exit criteria (AGENTS.md consistency).
- Create `scripts/language-catalog/{sync.sh,generate.py,overrides.toml}` skeleton + `references/language-catalog.json` schema doc.

### Phase 1 — Extraction script + manifest
- `sync.sh` fetches 71 docs (raw.githubusercontent, `--fail` per file), parses front-matter + `Tree-sitter:`/`Language Server:` bullets (python3 stdlib; tolerant of per-variant bullets, N/A, multiline links).
- Pins every grammar repo via `git ls-remote` (rev recorded; branch/tag kept informational); merges `overrides.toml`; emits `references/language-catalog.json`.
- Exit: manifest regenerates deterministically without network beyond `git ls-remote`; diff shows expected 71 entries with url+rev pairs; spot-check 10 entries vs docs + `git ls-remote` output.

### Phase 2 — Grammar catalog refactor + generator
- Split `builtin.rs` → family modules (existing 20 entries move, no behavior change; `cargo test --quiet` green before any new entry).
- Generator emits new family entries; run for new languages (~40 entries, all git-pinned; ~5-8 need override resolution when doc links are monorepos or non-git hosts).
- Extend `ee-ts-test-grammars` with a subset (toml, zig, lua, astro, vue) for tests.
- Exit: `tests/runtime` grammar catalog validation test — every entry has git url + non-empty rev, non-empty aliases/file_types; `ee do runtime fetch --all && ee do runtime build --all` succeeds locally; span/highlight smoke on new langs.

### Phase 3 — Bundled LSP defaults refactor + generator
- Split `Config::bundled()` → `bundled_defaults.rs` (existing 31 entries move verbatim; `bundled_config_preserves_current_defaults` test passes unchanged).

- Exit: updated `bundled_config_preserves_current_defaults` (new count + spot checks); boot test spawns a fake server per new id (existing `fake_language_server` harness); config override precedence tests unaffected.

### Phase 4 — Queries + injections

## 6.5 Long-term: filename/glob detection dimensions

**Implemented 2026-09-27.** `LanguageDefinition` gained `filenames` + `globs`; `Languages` and `RuntimeLoader` match with precedence glob > exact basename > extension; `**/`-aware glob matcher (syntax.rs `glob_matches`). Catalog overrides emit both dimensions; makefile (basenames), docker (filenames + `**/Dockerfile*` globs, real dockerfile grammar), and just (Justfile, `just-lsp` attach) ship on it. Old fallback that let extensions double as basenames is gone (COMMIT_EDITMSG-style names moved to `filenames`).

Remaining roadmap:

- `filenames` (exact basename match, e.g. `Makefile`, `GNUmakefile`, `Dockerfile`, `Justfile`, `CMakeLists.txt`, `Gemfile`, `Rakefile`, `COMMIT_EDITMSG`) — separates basename detection from extension detection, no more fake `"dockerfile"` extensions.
- `globs` (pattern match, e.g. `**/Makefile*`, `**/*.mk`) — already exists on `RuntimeLanguageConfig`, promote a matching dimension into `LanguageDefinition`.
- wire `first_line_match` (currently a dead field: stored into `first_line_regex`, never matched) for content-based detection (Dockerfile `FROM`, `# -*- makefile -*-`).
- resolve remaining deferred: gdscript, glsl, groovy, powershell, roc, sh, uiua.
- match precedence: glob > exact basename > first line > extension; ambiguity guard (equal priority, two owners) already exists in `index_language_file_types`.

Catalog pipeline: overrides gain `filenames = [...]` / `globs = [...]` keys; generator emits them into `LanguageDefinition`; loader consumes via the same lowercased index. Frontend override layers already carry `globs`/`first_line_regex` in `RuntimeLanguageConfig`, so RULE.md boundary is unchanged.

Beneficiaries beyond makefile: docker, just, cmake, ruby (Gemfile/Rakefile), git commit messages, env files.

## 7. Risks

| Risk | Mitigation |
| --- | --- |
| Grammar repo unreachable/forked/monorepo at sync time | `overrides.toml` repo correction; build failure surfaces at `runtime build`; defer language with manifest `status: deferred` |
| Zed doc lacks exact binary name (ansible, astro, dart, java) | `overrides.toml` curated per known-wonky server; doc install prose used as hint |
| Rev pin drift / upstream force-push | Exact rev pins in generated files; refresh only on explicit `--refresh-remote`; fetch validates rev exists |
| Fetch/build time grows (~46 git clones + compiles) | Selective `--language` fetch; CI builds subset; full build on release script |
| Fringe langs (roc, uiua) lack queries/crates | Excluded or minimal highlights; documented in manifest `status: deferred` |
| Injection misconfig in embedded langs | Phase 4 spot-verification + smoke test per embedded lang |
