# xi-unicode

This crate contains unicode utilites adapted for working with non-contiguous
bytes (such as a rope.)

Much of the contents of this repo are generated automatically by scripts from
Unicode data files.

This *current* file is the result of some archaeology; documentation on how to
rebuild the various files was missing, and I am attempting to reconstruct it.

## data

Constructing the various tables require the various data files. These are
available through the [components of the Unicode standard][components]
directory, for a given unicode version. In particular, we require
`LineBreak.txt`, plus `EastAsianWidth.txt` for the East Asian OP/CP splits used
by LB30. Both files currently live at the crate root; any directory holding them
works, since the data directory is passed on the command line.

- `src/tables/` is generated with the script located at `tools/mk_tables.py`,
  and can be built with,

  ```sh
  $ python3 tools/mk_tables.py . src/tables
  ```

  where the first argument is the data directory and the second is the module
  directory that receives `mod.rs` plus one file per constant group. The output
  is split so that no generated file crosses the 1000 LOC threshold:

  | file | constants |
  | --- | --- |
  | `lb1_2.rs` | `LINEBREAK_1_2` |
  | `lb3.rs` | `LINEBREAK_3_ROOT`, `LINEBREAK_3_CHILD` |
  | `lb4.rs` | `LINEBREAK_4_ROOT`, `LINEBREAK_4_MID`, `LINEBREAK_4_LEAVES` |
  | `state_machine.rs` | `N_LINEBREAK_CATEGORIES`, `LINEBREAK_STATE_MACHINE`, `LINEBREAK_STATE_MAP` |

  The group layout lives in `TABLE_SECTIONS` in the script. The writer refuses
  to emit a file at or above 1000 lines, so a Unicode update that outgrows a
  group fails loudly instead of silently exceeding the limit. `mod.rs` lists
  every re-export explicitly and is formatted the way `rustfmt` would format
  it, so `cargo fmt --check` stays clean; the constant arrays themselves are
  `#[rustfmt::skip]` and must not be hand-edited.

- the unit tests in `src/lib.rs` are also generated by this script, by passing
  the `--tests` and `--tests-str` flags (separately, to separate invocations) of
  the script, and then copying the output over into the body of these tests.
  These modes still print to stdout:

  ```sh
  $ python3 tools/mk_tables.py . --tests > /tmp/tests.rs
  ```

[components]: https://www.unicode.org/versions/components-14.0.0.html
